# 몬스터 레퍼런스 아카이브

로그인하지 않은 방문자에게는 포트폴리오(구글 슬라이드)를, 관리자 로그인 후에는 레퍼런스 아카이브를 보여 줍니다.

게임 몬스터 레퍼런스를 테마·외형·무기 태그로 묶어 검색하고, 전투 확장 시스템과 대응 PC 도구의 공략을 정리하는 페이지입니다.
PC든 폰이든 어느 기기에서 열어도 같은 데이터가 보이고, GIF·영상도 표에서 자동으로 반복 재생됩니다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 페이지 본체 |
| `config.js` | Firebase·Cloudinary 연결 정보와 편집 가능한 계정 |
| `firestore.rules` | Firebase에 붙여 넣을 보안 규칙 (누구나 보기, 등록 계정만 수정) |

## 무엇을 어디에 저장하나

| 저장소 | 저장하는 것 | 무료 한도 |
|---|---|---|
| Firebase (Firestore) | 게임·몬스터·태그·공략 글 | 1GB, 글 데이터만이라 사실상 무제한 |
| Cloudinary | 이미지·GIF·영상 원본 | 월 25크레딧 (1크레딧 = 저장 1GB 또는 보기 1GB) · 이미지 10MB, 영상 100MB까지 |

## 설정 순서 (처음 한 번, 약 20분)

### 1. Firebase 프로젝트 만들기
1. https://console.firebase.google.com 에 구글 계정으로 접속
2. **프로젝트 추가** → 이름 입력 (예: `monster-ref`) → Google Analytics는 꺼도 됩니다
3. 요금제는 무료(Spark) 그대로 둡니다

### 2. 웹 앱 등록 → config.js 채우기
1. 프로젝트 홈에서 **웹 아이콘 `</>`** 클릭 → 앱 이름 입력 → 등록 (Hosting 체크는 안 해도 됨)
2. 화면에 나오는 `firebaseConfig = { apiKey: ..., authDomain: ..., ... }` 값을 복사
3. `config.js`의 `firebase: { ... }` 안에 같은 항목끼리 붙여 넣기
4. `editors`에 본인 구글 이메일 입력

### 3. Firestore 데이터베이스 만들기
1. 왼쪽 메뉴 **빌드 → Firestore Database → 데이터베이스 만들기**
2. 위치는 `asia-northeast3 (서울)` 선택 → **프로덕션 모드**로 시작
3. 상단 **규칙** 탭 → 기존 내용을 지우고 `firestore.rules` 내용을 붙여 넣기
4. `'본인 구글 이메일'` 부분을 실제 이메일로 바꾸고 **게시**

### 4. 구글 로그인 켜기
1. **빌드 → Authentication → 시작하기**
2. **로그인 방법** 탭 → **Google** → 사용 설정 → 지원 이메일 선택 → 저장
3. **설정 → 승인된 도메인**에 GitHub Pages 주소 추가
   예: `내아이디.github.io` (뒤의 `/저장소이름`은 빼고 도메인만)

### 4-1. (선택) 구글 로그인이 막힌 곳에서 쓰기: 이메일·비밀번호 로그인
1. **Authentication → 로그인 방법 → 새 제공업체 추가 → 이메일/비밀번호** → 사용 설정 → 저장
2. **Authentication → 사용자 → 사용자 추가** → 이메일과 비밀번호 입력
   구글 계정과 같은 이메일은 쓸 수 없으니 `내아이디+work@gmail.com`처럼 `+별칭`을 붙이면 됩니다 (메일은 원래 메일함으로 옴)
3. **Authentication → 설정 → 사용자 작업**에서 **생성(가입) 사용 설정**을 끄기 (다른 사람이 계정을 못 만들게)
4. Firestore 규칙의 이메일 목록에 그 이메일 추가 후 게시
5. 페이지에서 로그인 → **또는 이메일로** 칸에 입력

### 5. Cloudinary (이미지·영상 저장) 만들기
1. https://cloudinary.com 에서 무료 가입 (카드 등록 없음)
2. 대시보드 왼쪽 위의 **Cloud name**을 복사 → `config.js`의 `cloudName`에 붙여 넣기
3. **Settings(톱니바퀴) → Upload → Upload presets → Add upload preset**
   - Upload preset name: `monster_ref` (config.js의 `uploadPreset`과 같게)
   - **Signing mode: Unsigned** ← 꼭 이걸로
   - Asset folder: `monster-ref` (선택, 파일 정리용)
   - 저장
4. 계정이 가득 차면 새 계정을 만들어 같은 방법으로 preset을 만들고, `config.js`의 `cloudinary` 목록에 한 줄 추가합니다. 새 파일은 마지막 계정으로 올라가고, 이전 파일은 원래 계정에서 계속 보입니다.

### 6. GitHub Pages에 올리기
1. GitHub에서 새 저장소 생성 (Public)
2. `index.html`, `config.js` 업로드 (`firestore.rules`, `README.md`도 같이 올려도 무방)
3. **Settings → Pages → Branch: `main` / `(root)`** → Save
4. 1~2분 뒤 `https://내아이디.github.io/저장소이름/` 으로 접속

### 7. 첫 데이터 넣기
1. 페이지 오른쪽 위 **구글 로그인**
2. 상태 표시가 `동기화 중 · 내이메일`로 바뀌면 **불러오기** → `data.json` 선택

## 쓰는 법

- **보기**: 링크만 있으면 누구나, 로그인 없이 볼 수 있습니다
- **추가·수정·삭제**: `editors`에 등록된 계정으로 로그인했을 때만 버튼이 보입니다
- **공략 메모**: 전투 확장 시스템·대응 PC 도구 칩에 마우스를 올리면 창이 뜨고, **수정**으로 편집합니다

### 이미지·영상 넣기
- 추가/편집 창에서 파일을 **끌어 놓거나, 파일 선택, 또는 Ctrl+V**로 붙여 넣으면 Cloudinary에 자동으로 올라갑니다
- PNG·JPG·GIF·WEBP는 10MB, MP4 등 영상은 100MB까지
- **10MB 넘는 움직이는 GIF**는 브라우저에서 영상으로 바꿔서 올립니다 (크롬·엣지에서만, GIF 길이만큼 시간이 걸림)
- 움직이는 GIF·영상은 표에서 소리 없이 자동 반복 재생되고, 화면에 보이는 것만 재생됩니다
- 이미지를 클릭하면 크게 보이고, **원본 열기**로 원본 GIF를 받을 수 있습니다
- 다른 사이트의 이미지 주소를 붙여 넣는 것도 됩니다 (원본 사이트에서 지우면 같이 안 보임)
- 이미지가 없고 유튜브 링크가 있으면 유튜브 썸네일을 대신 보여 줍니다

### 유튜브 링크 확인
- 페이지를 열 때마다 유튜브 링크가 아직 살아 있는지 자동으로 확인해서 링크 아래에 `● 재생 가능` / `✕ 삭제·비공개 의심`을 표시합니다
- 끊긴 링크가 있으면 검색창 옆에 **끊긴 링크 N** 버튼이 생기고, 누르면 그것만 모아 볼 수 있습니다
- 썸네일 유무로 판단하는 방식이라 대부분 정확하지만, **비공개로 바뀐 직후나 연령 제한 영상**은 살아 있는 것으로 보일 수 있습니다
- 유튜브가 아닌 링크는 확인하지 않습니다

### 백업 (버튼 한 번)
- 오른쪽 위 **백업**을 누르면 `monster-ref-backup-날짜.zip` 하나를 받습니다
  - `data.json`: 모든 글·태그·공략
  - `media/`: 이미지·GIF·영상 원본 전부 (`게임_몬스터_ID.확장자` 이름)
- **복원**: **불러오기**에 그 ZIP을 넣으면 글은 그대로 돌아오고, 원본 파일은 지금 `config.js`에 연결된 Cloudinary 계정으로 다시 올라갑니다
  Cloudinary 계정이 사라지거나 다른 계정으로 옮길 때도 이걸로 해결됩니다
- 한 달에 한 번 정도 받아 두는 걸 추천합니다

## 참고
- `config.js`의 Firebase apiKey와 Cloudinary 정보는 공개되어도 되는 값입니다. 글 수정은 `firestore.rules`가 막아 줍니다.
  다만 Cloudinary Unsigned 업로드는 설정을 아는 사람이 파일을 올릴 수는 있어서, 저장소를 Private으로 두거나(Pages는 유료 플랜 필요) 가끔 Cloudinary 미디어 목록을 확인하세요.
- 저장소가 Public이면 `config.js`에 적은 이메일도 공개됩니다. 원치 않으면 `editors`를 비워 두세요(규칙의 이메일만으로도 수정은 막힙니다).
- `config.js`를 비워 두면 클라우드 없이 그 브라우저에만 저장되는 모드로 열립니다.
